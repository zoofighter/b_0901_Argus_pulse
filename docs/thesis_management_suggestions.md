## 1. 🔗 Thesis 간 연관 관계 맵 (Cross-Thesis Links)

현재 9개 Thesis가 독립적으로 관리되지만, 실제로는 **서로 영향을 주고받는 관계**가 있습니다:

```
T-01 (데이터센터) ←→ T-05 (금리+데이터센터)    ← 거의 한 쌍
T-01 (데이터센터) ←→ T-08 (네오클라우드)        ← 수요 측면
T-02 (메모리)     ←→ T-07 (CXL 메모리)         ← 메모리 패밀리
T-06 (TPU vs GPU) ←→ T-08 (네오클라우드)        ← GPU 수요 양면
T-08 (네오클라우드) ←→ T-09 (GPU 금융)          ← CoreWeave 혈맹
```

### 구현 방법

`thesis.yaml`에 `related_theses` 필드를 추가:

```yaml
- id: "T-01"
  title: "2026 데이터센터의 변화"
  related_theses: ["T-05", "T-08"]
```

### 기대 효과

- 데일리 다이제스트에서 **"T-01이 강화되면 T-05도 영향 받음"** 같은 연쇄 분석 가능
- 블로그 주제 추천 시 연관 Thesis를 묶어서 **교차 관점 주제** 생성
- 예: "데이터센터 전력난(T-01) + 금리 인상(T-05) = CAPEX 둔화 리스크" 주제 자동 도출

## 2. 📅 Thesis 주간 리뷰 리포트

현재 산출물은 **매시간(뉴스) + 매일(다이제스트)** 단위인데, Thesis는 더 느린 주기로 움직입니다.

### 주간 리뷰 산출물 예시

```markdown
# 📊 주간 Thesis 리뷰 — 2026-W36 (9/1~9/7)

## confidence 변화 추이
| Thesis | 월초 | 현재 | 변동 | 추세 |
|---|---|---|---|---|
| T-01 데이터센터 | 80% | 85% | +5% | 📈 |
| T-06 TPU vs GPU | 70% | 62% | -8% | 📉 |

## 이번 주 핵심 이벤트가 바꾼 것
- T-02: 삼성 HBM4 퀄 통과 → 2강 체제 전환 가능성 ↑
- T-06: 구글 TPU v7 발표 연기 → GPU 수요 둔화 가설 약화

## 다음 주 주목할 이벤트
- NVIDIA GTC 발표 (9/10) → T-06, T-08, T-09 전체에 영향
```

### 구현 방법

- 워크플로우 계획의 **Phase 3 (daily_digest.py)**에 `--mode weekly` 추가
- 매주 일요일 21:00 cron 실행
- confidence 이력을 SQLite에 기록하여 추이 그래프 생성

## 3. 🏷️ Thesis에 "시간 범위(Time Horizon)" 추가

현재 가설에 **"언제까지 유효한 가설인가"**가 없습니다.

### 구현 방법

```yaml
- id: "T-03"
  title: "전고체 배터리의 변화"
  time_horizon: "2026H2~2028"           # 이 가설이 검증되는 시점
  milestone: "도요타 파일럿 라인 가동 발표"  # 핵심 판단 이벤트
  deadline_alert: true                   # 시점 접근 시 알림 여부
```

### 기대 효과

- 시스템이 **"T-03의 검증 시점이 다가오고 있습니다 — 현재 confidence 45%"** 사전 알림
- milestone 이벤트가 뉴스에 나타나면 **자동으로 Thesis 점검 트리거**
- 시간이 지나면서 자동으로 watch → archived 전환 제안

## 4. 📊 Thesis 우선순위 가중치 (Priority Weight)

9개 Thesis를 전부 동일 비중으로 추적하면, 블로그 추천에서 관심이 분산됩니다.

### 구현 방법

```yaml
- id: "T-01"
  priority: 5    # 최우선 — 블로그 추천에서 높은 가중치
- id: "T-07"
  priority: 2    # 관심은 있지만 당장 글감으로는 낮음
```

### 가중치 활용 방식

| priority | 의미 | 블로그 추천 | 알림 수준 |
|---|---|---|---|
| **5** | 최우선 | 매일 1개 이상 주제 보장 | 60점 이상 뉴스도 알림 |
| **4** | 높음 | 주 3~4회 주제 후보 | 70점 이상 알림 |
| **3** | 보통 (기본값) | 주 1~2회 주제 후보 | 80점 이상 알림 |
| **2** | 낮음 | 관련 뉴스 있을 때만 | 90점 이상만 알림 |
| **1** | 최저 | 거의 추천 안 됨 | 긴급 뉴스만 알림 |

### 기대 효과

- **"오늘 제일 쓰고 싶은 주제"**가 우선 추천됨
- 관심이 분산되지 않고 핵심 Thesis에 집중 가능
- priority는 사용자가 언제든 변경 가능 (관심 변화 반영)

## 5. 🔄 Thesis 자동 발굴 제안 (New Thesis Suggestion)

현재는 사용자가 직접 Thesis를 추가하는 구조인데, 매시간 뉴스를 모니터링하다 보면 **기존 9개에 포함되지 않는 새로운 패턴**이 반복될 수 있습니다.

### 구현 방법

데일리 다이제스트에 **"미분류 고득점 뉴스 클러스터"** 섹션 추가:

```markdown
## 💡 새 Thesis 후보 (기존 가설에 매칭되지 않은 고득점 뉴스)

### 후보 A: "휴머노이드 로봇 공급망의 부상"
- 관련 뉴스 3건, 평균 78점
  - 테슬라 옵티머스 2차 파일럿 생산 발표
  - 삼성전자 로봇용 고정밀 토크센서 양산
  - 중국 유니트리 B2 로봇 가격 파괴
- 잠재 관련 종목: Tesla, 삼성전자, 현대로보틱스

### 후보 B: "차량용 반도체 2차 사이클"
- 관련 뉴스 2건, 평균 72점
  - NXP 차량용 MCU 재고 소진 임박 발표
  - 현대차 전장 반도체 내재화 투자
- 잠재 관련 종목: NXP, Infineon, 현대차

🧑 사용자: 관심 있으면 thesis.yaml에 추가
```

### 자동 발굴 로직

```
1. 매시간 수집된 뉴스 중 기존 9개 Thesis 키워드에 매칭되지 않는 것 필터링
2. 미매칭 뉴스를 키워드 클러스터링 (TF-IDF 또는 LLM 분류)
3. 동일 클러스터가 3일 이상 반복되면 "새 Thesis 후보"로 추천
4. 사용자가 승인하면 thesis.yaml에 자동 추가
```

### 기대 효과

- **"내가 놓치고 있는 트렌드"**를 시스템이 잡아줌
- Thesis 목록이 시장 변화에 따라 유기적으로 진화
- 사용자의 Human-in-the-Loop 역할 강화 (추가 여부 최종 판단)

## 종합: 제안별 구현 우선순위

| 제안 | 구현 난이도 | 효용 | 추천 시기 |
|---|---|---|---|
| ④ 우선순위 가중치 | ⭐ (매우 쉬움) | 높음 | **Phase 1과 함께 즉시** |
| ③ 시간 범위 추가 | ⭐ (매우 쉬움) | 보통 | **Phase 1과 함께 즉시** |
| ① 연관 관계 맵 | ⭐⭐ (쉬움) | 높음 | Phase 1 이후 |
| ⑤ 자동 발굴 제안 | ⭐⭐⭐ (보통) | 높음 | Phase 2~3 이후 |
| ② 주간 리뷰 리포트 | ⭐⭐ (쉬움) | 보통 | Phase 3 이후 |

> **즉시 적용 권장**: ④ 우선순위 가중치와 ③ 시간 범위는 `thesis.yaml` 필드만 추가하면 되므로, Phase 1 구현 시 바로 반영하는 것을 권장합니다.
