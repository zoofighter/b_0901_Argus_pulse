# 블로그 글쓰기 양식 (Blog Writing Template)

> **작성일**: 2026-09-02  
> **목적**: 시스템이 생성하는 블로그 초안과 사용자가 수정·발행하는 최종본의 표준 양식 정의

---

## 1. 왜 양식이 필요한가

| 문제 | 양식이 해결하는 것 |
|---|---|
| 매번 다른 구조로 글이 나옴 | **일관된 구조** → 독자가 익숙해짐 |
| 어디서부터 수정해야 할지 모름 | **섹션별 역할** 명확 → 수정 포인트 분명 |
| 프론트매터가 빠져서 검색이 안 됨 | **표준 메타데이터** → 옵시디언에서 필터링·검색 가능 |
| 블로그 플랫폼에 올릴 때 재작업 | **마크다운 호환** → 티스토리·워드프레스에 바로 복붙 |

---

## 2. 블로그 글 표준 양식 (2-Page 기준)

### 옵시디언 저장 시 파일명 규칙

```
YYYY-MM-DD-blog-간결한-주제.md

예: 2026-09-02-blog-데이터센터-전력난.md
    2026-09-02-blog-삼성-HBM4-퀄통과.md
```

### 전체 템플릿

```markdown
---
title: "여기에 블로그 제목"
date: 2026-09-02
thesis: ["T-01"]
angle: "기술진화"
status: "draft"
tags: [데이터센터, 전력, 액체냉각, SMR]
trigger_news: "빅테크 전력 PPA 계약 급증 (85점)"
reading_time: "4분"
---

# 여기에 블로그 제목

> **한 줄 요약**: 이 글을 한 문장으로 요약 (독자가 읽을지 말지 결정하는 문장)

---

- 업계 동향

> - 수치 1: ...
> - 수치 2: ...
> - 출처: ...

- 분석과 해석

### 소제목 D
- 반대 의견 또는 리스크
- 균형 잡힌 시각

---

- 향후 모니터링 포인트 (날짜, 이벤트)
```

## 3. 프론트매터(Frontmatter) 필드 설명

| 필드 | 용도 | 값 예시 |
|---|---|---|
| `title` | 블로그 제목 | "데이터센터 전력난과 SMR 테마의 실체" |
| `date` | 작성일 | 2026-09-02 |
| `thesis` | 관련 Thesis ID | ["T-01", "T-05"] |
| `angle` | 주제 관점 (4대 프레임워크) | 기술진화 / 기업격돌 / 공급망병목 / 팩트체크 |
| `status` | 글 상태 | draft → review → published |
| `tags` | 검색/분류용 태그 | [데이터센터, 전력, 액체냉각] |
| `trigger_news` | 이 글을 쓰게 된 뉴스 | "MS 3GW 데이터센터 착공 (92점)" |
| `reading_time` | 예상 읽는 시간 | "4분" |

### 프론트매터의 활용

옵시디언에서 **Dataview 플러그인**으로 블로그 관리 가능:

```dataview
TABLE title, thesis, status, date
FROM "01_Inbox/Argus/blog"
WHERE status = "draft"
SORT date DESC
```

→ 아직 발행하지 않은 초안 목록을 한눈에 확인

## 4. 글 상태 흐름 (Status Flow)

```
┌──────────┐     시스템 생성      ┌──────────┐     사용자 수정      ┌──────────┐
│  (없음)   │ ──────────────────▶ │  draft   │ ──────────────────▶ │  review  │
└──────────┘                     └──────────┘                     └─────┬────┘
                                                                       │
                                                              사용자 발행 │
                                                                       ▼
                                                                 ┌──────────┐
                                                                 │ published│
                                                                 └──────────┘
```

| 상태 | 의미 | 누가 전환하는가 |
|---|---|---|
| **draft** | 시스템이 생성한 초안 | 시스템 (자동) |
| **review** | 사용자가 수정/검토 중 | 사용자 (수동) |
| **published** | 블로그에 발행 완료 | 사용자 (수동) |

---

## 5. 제목 스타일 3종 (시스템이 매번 3개 제안)

시스템이 블로그를 생성할 때, 항상 **3가지 스타일의 제목**을 제안합니다:

| 스타일 | 특징 | 예시 |
|---|---|---|
| **A형 (직관적 분석형)** | 팩트 중심, 신뢰감 | `[2026 인프라 리포트] 랙당 100kW 시대, 왜 빅테크는 변전소를 먼저 찾는가` |
| **B형 (도발적 의문형)** | 궁금증 유발, 클릭률 높음 | `GPU는 넘쳐나는데 전기가 없다? AI 데이터센터의 '전력망 절벽'` |
| **C형 (스토리텔링형)** | 몰입감, 공유 확산 | `공랭식 팬이 멈추던 날: 2026 AI 공장이 물 속으로 들어간 이유` |

→ 사용자가 원하는 스타일을 선택하거나, 3개를 조합하여 최종 제목을 결정

## 6. 4대 관점 프레임워크 (Angle)

모든 블로그는 다음 4가지 관점 중 하나로 작성됩니다:

| 관점 (Angle) | 생성 공식 | 독자에게 주는 가치 |
|---|---|---|
| **① 기술 진화형** | [새 기술] + [패러다임 변화] | "이 기술이 왜 게임체인저인지 이해할 수 있다" |
| **② 기업 격돌형** | [1위 수성] vs [후발 추격] | "누가 이기는지, 내 포지션을 어디에 잡을지 판단할 수 있다" |
| **③ 공급망 병목형** | [표면 호재] 뒤의 [진짜 병목] | "남들이 못 보는 진짜 리스크/기회를 볼 수 있다" |
| **④ 팩트체크형** | [대중의 환상] vs [현실] | "과대평가된 것과 과소평가된 것을 구분할 수 있다" |

## 8. 워크플로우 요약

```
1. 시스템이 블로그 아웃라인 3~5개 추천
           ↓
2. 사용자가 번호 선택 ("2번으로 써줘")
           ↓
3. 시스템이 표준 양식으로 2-Page 블로그 초안 생성
   → 옵시디언 blog/ 폴더에 저장 (status: draft)
   → 디스코드에 알림
           ↓
4. 사용자가 옵시디언에서 수정 (status: review)
           ↓
5. 사용자가 블로그 플랫폼에 발행 (status: published)
```
