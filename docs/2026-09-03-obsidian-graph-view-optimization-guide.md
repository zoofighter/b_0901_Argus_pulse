# 🌐 옵시디언 그래프 뷰(Graph View) 가독성 최적화 가이드

> **작성일**: 2026-09-03  
> **목적**: Argus Nexus 산출물 축적 시 옵시디언 그래프 뷰의 노드/글자 라벨 중복 및 시각적 산만함 해결  
> **핵심 원리**: 태그(Tag) 중심 군집화 유지 + 텍스트 라벨 페이드 아웃 + 가설(Thesis) 중심의 Hub & Spoke 양방향 링크 구조 확립

---

## 1. 문제 원인 분석

옵시디언 그래프 뷰에서 태그는 유의미한 허브 역할을 하지만, 다음과 같은 이유로 화면이 산만해집니다:
1. **과도하게 긴 파일명**: `2026-09-03-blog-삼성전자-CUBE-전략과-HBM4-대반격-메모리-파운드리-원팀의-승부수.md`처럼 40~60자의 긴 파일명이 그대로 노드 라벨로 노출되어 화면 전체를 텍스트로 뒤덮음.
2. **평면적 연결 구조**: 블로그, 스레드, 다이제스트가 모두 동일한 가중치로 태그 노드에 직접 매달려 꽃가루처럼 흩어지는 현상.
3. **그래프 뷰 기본 설정의 한계**: 줌 아웃 상태에서도 모든 파일의 텍스트 라벨을 100% 렌더링하도록 기본값이 설정되어 있음.

## 2. 해결책 1단계: 옵시디언 그래프 뷰(Graph View) 자체 설정 조절 (즉시 적용)

그래프 뷰 오른쪽 상단의 **설정(톱니바퀴 아이콘)**에서 아래 항목들을 조정합니다.

### ① 텍스트 페이드 임계값 조절 (가장 중요 ⭐)
- **경로**: `Display` ➔ `Text fade threshold`
- **설정**: 슬라이더를 **오른쪽(중간 이상)**으로 이동
- **효과**:
  - 축소(Zoom Out)된 전체 조망 화면에서는 글자가 사라지고 **깨끗한 색상 점(노드)들만 정갈하게 표시**됩니다.
  - 마우스를 노드 위로 올리거나(Hover), 휠로 특정 클러스터를 줌인(Zoom In)했을 때만 해당 글의 제목이 선명하게 나타납니다.

### ② 노드 물리 엔진(Forces) 거리 및 반발력 확대
- **경로**: `Forces`
- **조정 값**:
  - `Center force`: **낮춤 (0.3 ~ 0.4)** → 중앙으로 억지로 끌어당기는 힘을 줄임
  - `Repel force` (반발력): **높임 (10 ~ 15)** → 노드끼리 서로 밀어내어 글자끼리 겹치지 않게 분산
  - `Link distance` (연결선 길이): **넓힘 (100 ~ 150)** → 태그와 문서 간의 간격 확보

### ③ 시각적 구분을 위한 색상 그룹 (Color Groups) 지정
글자를 일일이 읽지 않아도 노드의 색상만으로 어떤 성격의 문서인지 즉시 파악하도록 설정합니다.
- `New group` 버튼을 눌러 쿼리와 색상을 지정:
  - `path:argus/Theses` ➔ **빨간색 (#FF4B4B)**: 투자 가설 허브 (가장 중요한 중심축)
  - `path:argus/Blog` ➔ **파란색 (#1E90FF)**: 2-Page 심층 분석 리포트
  - `path:argus/Thread` ➔ **초록색 (#00D26A)**: 모바일 압축 스레드
  - `path:argus/Review` ➔ **보라색 (#9B51E0)**: 사후 예측 검증 리포트
  - `tag:#삼성전자` ➔ **주황색 (#FF9800)**: 특정 기업 클러스터

### ④ 필터(Filters)를 활용한 뷰 분리
- 매일 쌓여서 그래프를 복잡하게 만드는 단순 일일 요약본은 그래프에서 숨깁니다:
  - `Filters` ➔ `Search files`에 `-path:argus/Digest` 입력
- `Orphans` (연결 없는 외딴 노드) 토글 해제.

## 3. 해결책 2단계: Argus Nexus 시스템 생성 방식 최적화

코드 레벨에서 생성물 파일명과 본문 링크 구조를 최적화하여 그래프의 가독성을 근본적으로 개선합니다.

### A. 파일명 슬러그(Slug) 15자 내외 압축
- **기존 방식**: 제목 전체를 파일명에 반영  
  `2026-09-03-blog-삼성전자-CUBE-전략과-HBM4-대반격-메모리-파운드리-원팀의-승부수.md` (라벨 55자)
- **개선 방식**: 날짜 + 핵심 키워드 2~3개로 파일명 슬러그 압축  
  `2026-09-03-삼성전자-CUBE-HBM4.md` (라벨 15자 내외)
- *실제 장문의 풀 타이틀은 마크다운 본문의 `# 제목` 및 YAML Frontmatter `title: "..."`에 온전히 보존되므로 문서 품질에는 전혀 영향이 없음.*

### B. Thesis 중심의 'Hub & Spoke(방사형 꽃 모양)' 링크 구조
- 개별 블로그/스레드가 태그에만 매달리지 않고, 상위 개념인 **투자 가설 노트(`[[T-XX]]`)**에 위키링크로 직접 결합되도록 구성:
  ```markdown
  ---
  title: "삼성전자 CUBE 전략과 HBM4 대반격"
  thesis: ["T-02", "T-16"]
  ---
  
  관련 가설: [[T-02-메모리-산업의-변화]], [[T-16-반도체-패키징-혁신]]
  ```
- **그래프 시각화 효과**:
  - 태그 주변에 글들이 무질서하게 흩어지는 대신, **`T-02`라는 핵심 가설 노드를 중심으로 관련 블로그, 스레드, 리뷰가 꽃잎처럼 방사형으로 묶이게 됩니다.**
