## 1. Thesis란?

**Thesis(테제)**란 사용자가 현재 추적하고 있는 **투자 가설** 또는 **산업 변화 방향성**입니다.

단순한 "관심 키워드"가 아니라, **"이 방향으로 세상이 움직일 것이다"**라는 방향성 있는 주장이며, 시스템은 이 가설을 지속적으로 **지지/반박하는 근거를 수집·점검**합니다.

```
예시:
  ❌ "HBM에 관심 있다"          ← 단순 키워드
  ✅ "HBM4 커스텀 시대 진입으로  ← 방향성 있는 가설
     메모리 산업의 ASIC화가 가속된다"
```

### 상태 전이 규칙

| 상태 | 의미 | 시스템 동작 |
|---|---|---|
| **active** | 적극 추적 중 | 4시간마다 점검, 블로그 주제 필터에 포함, 이상 감지 대상 |
| **watch** | 관찰 모드 | 점검 빈도 감소 (12시간), 블로그 주제에서 가중치 하향 |
| **archived** | 보관 (비활성) | 점검 중지, 블로그 필터에서 제외. 과거 기록은 RAG에 남음 |

## 5. Thesis가 시스템에서 하는 3가지 역할

### ⓐ 블로그 주제 추천의 **필터**

```
  [매시간 수집되는 뉴스] ─┐
                         ├─▶ LLM 주제 생성기 ─▶ 블로그 주제 추천
  [Thesis = 필터/렌즈]  ─┤
                         │
  [배경지식 = 컨텍스트]  ─┘
```

- 같은 뉴스라도 Thesis가 다르면 **완전히 다른 주제**가 추천됨
- 예: "TSMC 2nm 수율 뉴스"
  - T-01 (데이터센터) 관점 → "CoWoS 병목과 데이터센터 확장 지연"
  - T-02 (메모리) 관점 → "HBM4 베이스다이 3nm 파운드리 경쟁"
  - T-06 (TPU vs GPU) 관점 → "구글 TPU가 TSMC 2nm를 선점하면?"

### ⓑ Thesis 점검 보고서 생성 (4시간 주기)

[Thesis Checker 에이전트](file:///Users/boon/Dropbox/03_code/b_0901_Argus_pulse/docs/implementation_plan.md#L92)가 각 active Thesis에 대해:

1. **지지 근거** 수집 (최근 뉴스 + RAG)
2. **반박 근거** 수집
3. **신뢰도(confidence) 재계산**
4. **판단** 제시 (유지 / 수정 / 경고)

```markdown
## 가설 #1: 데이터센터 전력 병목
- 신뢰도: 82% (↑2% from last)
- 지지 근거: 빅테크 SMR 부지 선점 가속, 전력 PPA 경쟁 심화
- 반박 근거: 구글 효율 개선으로 데이터센터당 전력 소비 감소 발표
- 판단: 가설 유지, 단 효율 개선 트렌드 모니터링 필요
```

### ⓒ 이상 신호 알림의 **트리거**

Thesis 관련 키워드가 포함된 뉴스가 **비정상적으로 급증**하거나, 고득점 뉴스가 **가설과 반대 방향**일 때 즉시 알림:

```
🚨 [T-06 관련 이상 신호]
"엔비디아, 차세대 B300 GPU에서 CUDA 커널 자동 최적화 탑재 — TPU 가성비 우위 축소 가능성"
→ T-06 (TPU 증가로 GPU 수요 둔화) 가설에 대한 반박 신호
```

## 6. Thesis 관리 워크플로우

### 사용자가 하는 일 (Human-in-the-Loop)

| 작업 | 방법 | 빈도 |
|---|---|---|
| **새 Thesis 추가** | `thesis.yaml`에 새 항목 추가 | 수시 |
| **가설 내용 수정** | `hypothesis`, `direction` 필드 편집 | 점검 보고서 확인 후 |
| **상태 전환** | `status`를 active → watch → archived | 주기적 리뷰 |
| **키워드 보강** | `keywords` 배열에 새 키워드 추가 | 새 트렌드 발견 시 |
| **관련 종목 갱신** | `related_companies` 업데이트 | 산업 구조 변화 시 |

### 시스템이 자동으로 하는 일

| 작업 | 주기 | 설명 |
|---|---|---|
| **Thesis 점검** | active: 4시간 / watch: 12시간 | 지지/반박 근거 수집, 신뢰도 갱신 |
| **confidence 갱신** | 매 점검 시 | 최신 뉴스 + RAG 기반 재계산 |
| **last_checked 업데이트** | 매 점검 시 | 마지막 점검 시각 기록 |
| **블로그 주제 필터링** | 매시간 (뉴스 수집 시) | active Thesis 기준으로 주제 추천 |
| **이상 신호 감지** | 실시간 | Thesis 키워드 관련 급변 감지 |

## 7. Thesis와 다른 시스템 구성요소의 관계

```
thesis.yaml
    │
    ├──▶ [블로그 주제 생성기]     뉴스 × Thesis(필터) × 배경지식 → 주제 추천
    │    (blog_topic_generator)
    │
    ├──▶ [Thesis Checker Agent]  4시간마다 가설 지지/반박 근거 수집 → 점검 보고서
    │    (agents/thesis_checker)
    │
    ├──▶ [Researcher Agent]      Thesis 키워드로 RAG 검색 범위 조정
    │    (agents/researcher)
    │
    ├──▶ [이상 신호 감지]         Thesis 키워드 뉴스 급증/반전 시 즉시 알림
    │    (anomaly detection)
    │
    └──▶ [심층 보고서]            섹터별 동향에서 Thesis 관련 내용 우선 배치
         (deep report)
```

## 8. 미결 사항

> [!IMPORTANT]
> ### 사용자 정의가 필요한 항목
> 
> | 항목 | 현재 상태 | 필요한 결정 |
> |---|---|---|
> | 각 Thesis의 `direction` | 미정 | 상승(bullish)/하락(bearish)/중립(neutral) 판단 |
> | 각 Thesis의 초기 `confidence` | 미정 | 0~100 사이 초기값 설정 |
> | 점검 빈도 커스터마이징 | 기본값 (active:4h, watch:12h) | 조정 필요 시 |
> | Thesis 간 연관 관계 | 미정의 | T-01↔T-05 (데이터센터+금리) 등 교차 분석 여부 |
> | Thesis 최대 개수 제한 | 없음 | 너무 많으면 LLM 비용 증가 — 권장 15개 이하 |
