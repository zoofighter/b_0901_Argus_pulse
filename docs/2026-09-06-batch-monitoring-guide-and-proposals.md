## 1. 개요 (Background)

Argus Pulse는 24시간 동안 정기 크론(Cron) 및 스케줄러를 통해 뉴스 수집, 주제 추천, 2-Page 블로그 자동 집필, 사후 검증 리뷰, 일일 다이제스트를 자율 실행합니다.

본 문서는 현재 운영 중인 **배치 실행 모니터링 방법**을 정리하고, 비대화형 환경에서 발생할 수 있는 **침묵의 실패(Silent Failure)**와 **macOS 절전 모드 이슈**를 원천 차단하기 위한 **4대 모니터링 고도화 방안**을 제시합니다.

## 2. 현행 배치 모니터링 방법 (Current Methods)

### ① 실시간 로그 및 프로세스 확인 (터미널 CLI)
각 파이프라인 작업의 표준 출력과 에러는 `logs/` 디렉터리에 개별 로그 파일로 누적 기록됩니다.

```bash
# 1. 아침 08:00 주제 추천 & 블로그 자동 집필 로그 실시간 확인
tail -n 30 -f logs/cron_topic.log

# 2. 매시간(09:00 ~ 21:00) 실시간 뉴스 감시 로그 확인
tail -n 30 -f logs/cron_monitor.log

# 3. 오후 13:00 사후 검증 리뷰 로그 확인
tail -n 30 -f logs/cron_review.log

# 4. 야간 21:00 데일리 다이제스트 & Thesis 점검 로그 확인
tail -n 30 logs/cron_digest.log logs/cron_checker.log

# 5. 백그라운드 활성 프로세스 점검
ps aux | grep -E "python.*(topic|monitor|review|digest|scheduler)" | grep -v grep
```

### ② 디스코드(Discord) 웹훅 채널 확인
* **08:00 / 13:05**: 추천 기획안 3선 도착 알림 (`💡 오늘의 콘텐츠 기획안이 도착했습니다.`)
* **블로그/스레드 집필 완료**: 마크다운 파일 저장 알림 (`✅ BLOG 초안 생성 완료`)
* **실시간 핫 뉴스 감지**: 80점 이상 충격 뉴스 인입 즉시 알림 (`🚨 [속보/고득점 뉴스]`)

### ③ 산출물 생성 확인 (로컬 & 옵시디언)

## 3. 현행 모니터링 방식의 핵심 한계 (Pain Points)

> [!WARNING]
> **현재 방식의 3대 운영 취약점**
> 
> 1. **침묵하는 실패 (Silent Failure)**:  
>    API 할당량 초과, 비대화형 입력 대기(`EOFError`), 네트워크 단절 등으로 스크립트가 죽을 경우, 로그 파일에만 기록되고 디스코드로 실패 알림이 오지 않아 사용자는 "배치가 아예 안 돌았나?" 하고 오해하게 됩니다.
> 2. **macOS 절전 모드(Sleep / Clamshell) 건너뜀**:  
>    macOS 기본 `cron`은 맥북 덮개가 닫혀 있거나 디스플레이 슬립 상태일 때 맥을 깨우지 못하며, 해당 시각의 배치 작업을 건너뜁니다.
> 3. **통합 상태 가시성(Observability) 부재**:  
>    하루 24시간 파이프라인(08:00 ➔ 09~21:00 ➔ 13:00 ➔ 21:00) 중 "어떤 작업이 성공했고, 어떤 작업이 대기 중인지" 한 화면에서 점검하는 단일 명령어가 없습니다.

### 제안 2. 배치 실패 시 디스코드 '긴급 에러 경보' (Failure Trap & Alert) ⭐ [필수]
* 배치 실행 스크립트가 예외를 던지거나 `exit code != 0`으로 비정상 종료 시, 즉시 디스코드로 **🚨 빨간색 에러 임베드(스택 트레이스 요약 및 발생 모듈)**를 전송합니다.
* 사용자가 터미널을 열어보지 않아도 "어느 단계에서 왜 멈췄는지" 디스코드로 즉각 인지할 수 있습니다.

### 제안 3. 옵시디언 '시스템 상태 대시보드 노트' 자동 갱신
* 배치가 실행될 때마다 옵시디언 내 [`agent_vault/argus/System-Status.md`](file:///Users/chansoojeon/Library/Mobile%20Documents/iCloud~md~obsidian/Documents/agent_vault) 파일을 자동 갱신합니다.
* 마크다운 표 및 콜아웃을 통해 옵시디언 앱 내부에서 오늘 배치의 정상 구동 여부를 즉시 파악할 수 있습니다.

### 제안 4. macOS 네이티브 `launchd` 데몬 전환 (절전모드 극복)
* `cron` 대신 macOS 권장 표준인 `launchd` 서비스(`.plist`)로 스케줄러를 등록합니다.
* **Catch-up 기능**: 맥북이 절전 상태였다가 09:30에 깨어나면, 놓쳤던 08:00 배치를 감지하여 즉시 실행해 줍니다.
* 필요 시 `caffeinate`를 연동하여 특정 배치 실행 시각에 맥북이 잠들지 않도록 제어할 수 있습니다.
