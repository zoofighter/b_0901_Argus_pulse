## 단계 ① 블로그 주제 추천 (Human in the Loop)

### 동작 방식

```
[아침 08:00 자동 실행] 또는 [사용자가 수동 실행]

1. 최근 24시간 고득점 뉴스 15건 추출 (b_0826 SQLite)
2. 9개 Thesis와 교차 분석
3. LLM이 블로그 아웃라인 3~5개 생성
   - 제목 (3종 스타일)
   - 관점 (기술진화 / 기업격돌 / 공급망병목 / 팩트체크)
   - 2-Page 목차 (서론-본론1-본론2-결론)
4. 디스코드/터미널에 추천 목록 표시

🧑 사용자: "2번으로 써줘"

5. 선택한 주제로 2-Page 블로그 본문 자동 생성
6. 옵시디언 저장 + 디스코드 전송
```

### Human in the Loop가 필요한 이유

| AI가 자동으로 하는 것 | 사람이 판단하는 것 |
|---|---|
| 뉴스와 Thesis 교차 분석 | **"오늘 이 주제가 쓸 만한가?"** |
| 아웃라인/목차 생성 | **"이 각도가 맞나? 다른 관점은?"** |
| 블로그 본문 초안 작성 | **"게시해도 되는 퀄리티인가?"** |

→ AI가 80%를 하고, 사람이 20%의 핵심 판단을 내리는 구조

## 단계 ①-R 과거 블로그 리뷰 (새 블로그가 없는 날)

### 역할

오늘 고득점 뉴스가 부족하여 새 블로그를 생성하지 않는 날, **과거 발행된 블로그의 예측을 현재 뉴스와 대조하여 검증 리뷰를 자동 생성**한다. 단순 아카이브 재탕이 아니라, Thesis 장기 검증 루프의 핵심 기능이다.

### 동작 방식

```
[아침 08:00 판단]

오늘 고득점 뉴스 < 2건?
    ↓
1. ChromaDB(argus_reports)에서 리뷰 대상 블로그 선정
   - 30 / 90 / 180일 경과 기준
   - 당시 이후 Thesis Confidence 변화가 ±20 이상인 것
   - 마지막 리뷰 후 가장 오래된 것
2. 선정된 블로그 원문 + 최신 뉴스 → LLM 비교 분석
3. "당시 예측 vs 현재 상황" 리뷰 블로그 자동 생성
4. 옵시디언 저장 + 디스코드 전송
5. 리뷰 블로그도 ChromaDB에 재인제스트 (Knowledge Flywheel)
```

### 리뷰 대상 선정 기준

| 선정 기준 | 설명 | 우선순위 |
|---|---|---|
| **Thesis Confidence 변화** | 당시 이후 신뢰도가 ±20 이상 바뀐 Thesis | ⭐⭐⭐ |
| **경과 기간 milestone** | 30일 / 90일 / 180일 경과한 블로그 | ⭐⭐⭐ |
| **RAG 인출 빈도** | 최근 검색에서 자주 참조된 문서 | ⭐⭐ |
| **방치 기간** | 마지막 리뷰 이후 가장 오래된 것 | ⭐⭐ |
| **당시 불확실성** | 발행 시 Confidence가 낮았던 글 | ⭐ |

### 리뷰 블로그 포맷

```markdown

> 원본: 2026-03-15 발행 | 리뷰: 2026-09-02

- Thesis T-02 신뢰도: 62점 (불안정)

## 🔄 그 이후 무슨 일이 있었나 (최신 뉴스 기반)
- 2026-06: 삼성 HBM4 수율 개선, 엔비디아 2차 퀄 통과
- 2026-08: 삼성 HBM4 본격 납품 시작

## ✅ 예측 정확도 평가
- 예측: ❌ 틀림 (수율 회복 속도를 과소평가)
- Thesis T-02 신뢰도 변화: 62 → 81점 (+19)

## 💡 배운 점 / 업데이트된 관점
- 삼성의 수율 개선 속도는 시장 예상보다 빨랐음
- 향후 HBM5 경쟁에서도 같은 패턴 반복 가능
```

### Human in the Loop 여부

| 항목 | 새 블로그 생성 | 리뷰 블로그 생성 |
|---|---|---|
| 주제 선택 | 🧑 사람이 선택 | 🤖 시스템이 자동 선정 |
| 초안 검토 | 선택적 | 선택적 |
| 이유 | 새 주제의 방향성 판단 필요 | 비교 분석은 객관적 기준 존재 |

→ 리뷰 블로그는 **완전 자동화**가 가능. 결과물은 옵시디언에서 사후 확인.

### 부가 효과

1. **Thesis 장기 추적** — 분기/반기 단위 예측 정합성 자동 점검
2. **Knowledge Flywheel 강화** — 리뷰 블로그도 RAG 재인제스트 → 다음 분석에 활용
3. **콘텐츠 일관성** — 뉴스가 없는 날도 매일 발행 리듬 유지
4. **자기 교정** — "나는 어떤 예측을 자주 틀리는가" 패턴 축적


```
2. 4축 스코어링 (긴급성, 관련성, 신뢰도, 영향력)

    ↓

    ↓
[점수 60~79]   → 📋 로그에 축적 (오후/저녁 정리 대상)
    ↓
```

## 구현 로드맵 (3단계, 약 3~5일)

### Phase 1: 블로그 추천 + 생성 (Day 1~2)

| 파일 | 역할 |
|---|---|
| `thesis.yaml` | 9개 Thesis 구조화 저장 |
| `topic_generator.py` | 뉴스+Thesis 교차 → 아웃라인 추천 |
| `blog_writer.py` | 선택한 아웃라인 → 2-Page 블로그 생성 |
| `config.py` | API 키, 경로, 설정 |

```
사용 흐름:
$ python topic_generator.py          # 오늘의 블로그 주제 3~5개 추천
$ python blog_writer.py --topic 2    # 2번 주제로 블로그 생성
```

### Phase 2: 매시간 모니터링 (Day 2~3)

| 파일 | 역할 |
|---|---|
| `hourly_monitor.py` | 뉴스/블로그/트위터 수집 + 스코어링 |
| `sources.yaml` | 수집 대상 RSS, 트위터 계정 목록 |
| `notifier.py` | 고득점 즉시 알림 (디스코드/텔레그램) |

```
자동 실행:
$ crontab -e
0 9-21 * * * cd /path/to/argus_pulse && python hourly_monitor.py
```

### Phase 3: 데일리 정리 (Day 3~5)

| 파일 | 역할 |
|---|---|
| `daily_digest.py` | 하루 뉴스 종합 → Thesis별 정리 → MD 생성 |
| `templates/digest.md` | 다이제스트 마크다운 템플릿 |

```
자동 실행:
0 15 * * * cd /path/to/argus_pulse && python daily_digest.py --mode midday
0 21 * * * cd /path/to/argus_pulse && python daily_digest.py --mode full
```

### Phase 4: 과거 블로그 리뷰 (Phase 1 안정화 후)

| 파일 | 역할 |
|---|---|
| `review_generator.py` | 리뷰 대상 선정 + 비교 분석 + 리뷰 블로그 생성 |
| `topic_generator.py` | 조건 분기 추가 (새 블로그 vs 리뷰 블로그) |

```
동작:
- 매일 아침 topic_generator.py 실행 시 자동 판단
- 고득점 뉴스 < 2건이면 review_generator.py 호출
- 결과물: 옵시디언 저장 + 디스코드 전송 + ChromaDB 재인제스트
```
